Cache in Our Django CRM

The exact files, code flow, live demo, and the next directions after this basic implementation.

1
Today

What did we add?

One cache type

Django LocMemCache: temporary memory inside Django.

One cached value

customer_list: the list shown on the customer page.

One visible proof

The browser displays whether the page used database or cache.

Goal: see a cache miss first, then a cache hit after refresh.

Every refresh repeated the database query, even if no customer data changed.

3
Our decision

We chose local-memory application cache

LocMemCache

A built-in Django cache stored in this Django process’s RAM.

Why for this class?

Simple setup, fast enough to demonstrate, and no new service to install.

This is an application cache, not a browser cache or CDN cache.

4
No new package

We used Django’s built-in cache support

from django.core.cache import cache

What we did not add

No Redis, Memcached server, Docker container, or package in requirements.txt.

Why that matters

Students can focus first on key, value, hit, miss, TTL, and clearing old data.

Django itself provides cache.get(), cache.set(), and cache.delete().

6
Settings

Tell Django which cache to use

crm/crm/settings.py

CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.locmem.LocMemCache',
        'LOCATION': 'crm-class-cache',
        'TIMEOUT': 60,
    }
}

BACKEND

The cache engine: local memory.

LOCATION

A name for this memory store.

TIMEOUT

Default lifetime: 60 seconds.

8
The key and the question

Where does Django ask cache?

crm/registration/views.py

cache_key = 'customer_list'
data = cache.get(cache_key)

Key

customer_list is the label for this cached customer-list value.

get()

It asks: “Do you have a value saved with this exact key?”

Cache does not use intent detection here. It receives the exact key written by the developer.

Cache miss

If no saved value exists

if data is None:
    data = list(Registration.objects.values(
        'id', 'name', 'email', 'date_of_birth'
    ))
    cache.set(cache_key, data, timeout=60)

customer_list
→
Read PostgreSQL
→
Save data for
60 seconds

This is a cache miss. We save only safe display fields; the plain-text password field is not cached.

Cache hit

If cache already has the value

else:
    cache_status = 'Fast memory used: cache hit'
Refresh customer page
→

customer_list
→

→
No PostgreSQL query

This is a cache hit: fast memory returns the temporary copy.

11
Keep data fresh

Clear cache after customer changes

cache.delete('customer_list')

Create

New customer added → old list is no longer complete.

Edit

Customer changed → cached name/email may be old.

Delete

Customer removed → cached list may still show them.

Deleting the old cache key makes the next request fetch and save fresh database data.

Live demo

What should students see?

ActionBrowser messageWhat happened?

A Django restart also clears this local-memory cache. That is expected.

13
Trade-off

Why not use this exact cache forever?

Good for today

  • Built into Django
  • No external service
  • Fast and easy to understand

Limits

  • Disappears after restart
  • Each Django process has its own copy
  • Not shared across multiple servers

Next production-level direction: a shared cache such as Redis or Memcached.
